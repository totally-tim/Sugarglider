---
title: Contexts (experimental)
description: Named sets of windows with their own tiling layouts
---

Contexts are an experimental feature: named sets of windows that you switch between. Each context keeps its own tiling layout. Switching shows its windows and parks the others at a bottom corner. A parked window may leave a strip up to 1 point wide and 32 points tall on its display. Sugarglider closes nothing, and a window can belong to several contexts.

:::caution[Experimental]
Contexts are off by default. The switcher, per-screen scope, and command line are implemented. One-display TextEdit parking has been measured, but full context switching, other apps, and two-display behavior still need hands-on macOS checks.
:::

## Turn it on

Turn on **Contexts (experimental)** in the Preferences window, or set the flag in your config file:

```toml
[settings.experimental]
contexts.enable = true
```

Run `sugarglider config update` to load the edited file, or `sugarglider config update --watch` to reload on every save. With the flag off, Sugarglider behaves as it did before contexts.

## Create a context

Make a context from the windows that show on the visible Spaces.

- Menu bar: **New Context from Current Windows…**
- Command line: `sugarglider context create "Client work"`

The new context becomes the active one, and its layout starts as the current layout. Parked windows are left out. A pinned window gets no record in the new context, because it already belongs to every context.

## Switch contexts

Switch with a key binding, the menu bar, or the command line. The default config leaves the context bindings commented out, so add the ones you want under `[keys]`:

```toml
[keys]
"Ctrl + Alt + 0" = "show_everything"
"Ctrl + Alt + 1" = { switch_context = 1 }
"Ctrl + Alt + 2" = { switch_context = 2 }
# ... through 9
"Ctrl + Alt + Tab" = "previous_context"
"Ctrl + Alt + Space" = "open_context_switcher"
```

- `switch_context` takes a context number from 1 to 9 or a name. Part of a name works: "cli" finds "Client work".
- `show_everything` shows every window again.
- `previous_context` returns to the context you used before the current one.

The status item shows the active context, shortened if the name is long. Its menu lists your contexts, followed by **Show Everything**, **New Context from Current Windows…**, **Send Window to**, and **Open Switcher…**. If you bind `switch_context` by number, the menu shows that shortcut beside the context with that number.

**Open Switcher…** opens the search panel. Type to find a context, then press Enter to switch. The suggested binding is `Ctrl + Alt + Space`.

The command line switches by number or by name:

```bash
sugarglider context switch cli
sugarglider context switch 2
sugarglider context switch --name 2024
```

Use `--name` when a context's name is made of digits, so the command doesn't read it as a number. On failure the command prints the reason and exits with status 1.

## Add, move, and pin windows

| Action | How |
|---|---|
| Add the focused window to a context | Key binding `add_window_to_context`, or `sugarglider context add <query>` |
| Move the focused window to another context | Key binding `move_window_to_context`, the menu's **Send Window to**, or `sugarglider context move <query>` |
| Remove the focused window from the active context | Key binding `remove_window_from_context`, or `sugarglider context remove` |
| Pin or unpin the focused window | Key binding `toggle_window_pinned`, or `sugarglider context pin` |

An added window stays where it is until the next switch, even if you move between Spaces in the meantime. Moving and removing take effect at once, and a window that no longer belongs to the context you are in is parked. Focus moves to a window that stays.

A **pinned** window belongs to every context, including contexts you create later. It also shows under Unsorted, but it doesn't count as an unsorted window.

## Everything and Unsorted

Two built-in entries sit next to your contexts.

**Unsorted** holds the windows that are in no named context. It appears only while it has windows. You can't rename, number, or delete it.

**Everything** shows every window in the normal layout, as if contexts were off. It is active until you create your first context. To return to it, press your `show_everything` binding, choose **Show Everything** in the menu, or run:

```bash
sugarglider context everything
```

Quitting Sugarglider puts every parked window back too.

## The command line

The context commands are:

```
sugarglider context list [--json]
sugarglider context current [--json]
sugarglider context create <name>
sugarglider context switch <query>
sugarglider context add <query>
sugarglider context everything
sugarglider context previous
sugarglider context move <query>
sugarglider context remove
sugarglider context rename <query> <new-name>
sugarglider context delete <query>
sugarglider context number <query> <number>
sugarglider context pin
sugarglider context forget <query> <record>
```

`list` prints one line per entry, with a star on the active one. `--json` prints the snapshot as JSON, and `current` prints the active context's name. `pin` toggles pinning for the focused window. `forget` removes a gone window's member record from a named context. Use its zero-based `members[].record` value from `context list --json`; an open window's record cannot be forgotten.

## Safety

Switching never closes a window. Before Sugarglider parks a window, it writes the window's frame to `~/.glide/parked.json`. If Sugarglider quits or crashes, the next launch reads that file and puts the windows back. The contexts and their members live in `~/.glide/contexts.json`. Both files contain window titles.

Sugarglider checks the frame that macOS reports after parking. It accepts only a bottom-corner strip within the 1 by 32 point limit, with no overlap on another display. If a window cannot meet that limit, the context switch fails, Sugarglider shows Everything, and it restores parked windows from their saved frames. Some apps or display arrangements may therefore prevent a context from staying active. One-display TextEdit testing confirmed a 1 by 32 point strip; other apps and two-display setups still need physical QA.

## Per-screen scope

Choose **All screens** or **Focused screen** under **Contexts (experimental)** in Preferences. The same setting is available in the config file:

```toml
[settings.experimental.contexts]
enable = true
scope = "per_screen"
```

With `global` scope, a switch changes every screen. With `per_screen` scope:

- Each screen has its own active context, and a switch changes only the focused screen.
- A window shared by two contexts appears on one screen only, and goes to the screen that switched most recently.
- The screen it leaves closes the visible gap while the window is away and keeps the window's saved position for its return.

Changing from `per_screen` to `global` uses the focused screen's context for every screen. This also applies when you change the config while Sugarglider is stopped: on the next launch, it chooses the current focused screen's saved context and saves the global choice. If no focused window is known at startup, it uses the first screen. Changing from `global` to `per_screen` gives every screen the current global context.

## Checks still pending

The M1 physical parking spike and manual QA on a live Mac are pending. These include two-display switching, recovery after a crash, and the Raycast and SuperCmd paths.

:::note[The switcher hotkey and macOS]
The suggested switcher binding is ⌃⌥Space, which macOS also uses for "Select next source in Input menu". Sugarglider's event tap takes a bound key before macOS sees it, and it swallows a bound key even when contexts are off. The default config leaves the context bindings commented out for this reason.
:::
